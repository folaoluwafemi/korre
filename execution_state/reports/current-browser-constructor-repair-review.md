- **The journal addresses a real partially constructed object.** Babylon registers the instance at `abstractEngine.pure.js:1165`, adds its mobile-check resize listener through `_setupMobileChecks` (`thinEngine.pure.js:145`, `abstractEngine.pure.js:1361`), and adds context listeners before its context-acquisition failure. Since a throwing `new Engine` does not assign the caller's `engine`, ordinary cleanup alone cannot reach that object. `createPreviewEngine` now surrounds exactly that synchronous constructor call with a listener journal and preexisting-engine identity snapshot.
- **Cleanup has bounded ownership.** It records successful registrations by exact target/type/listener/capture, removes those registrations on constructor failure, and removes only registry identities absent from the preceding snapshot. Existing engines remain in the array; no entire registry reset occurs. Inspected pinned constructor listener functions are newly allocated for that engine. JavaScript constructor execution is synchronous; the journal does not span an await or later unrelated work. It is not a general-purpose transaction for arbitrary reentrant third-party monkeypatching, nor a proof of every hypothetical later driver allocation failure.
- **Wrapper restoration and receiver typing are explicit.** `finally` restores the original prototype method when the wrapper still owns that slot; successful construction retains actual listeners for normal engine disposal. It introduces no pure-rules, server or protocol dependency. Instance count is attached only when the injected lifecycle harness object already exists; the application does not create a production diagnostic global.
