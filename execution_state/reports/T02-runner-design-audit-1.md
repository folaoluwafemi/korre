# T02 canonical shot-runner design audit 1

**Verdict: design audit only; T02 remains open.** The existing evidence supports a real-WASM world constructor and a complete calibration matrix, but it does not yet demonstrate a canonical shot runner, whole-button loft, all-body safe settling, or the required simulation facts and playback. I read the source, contracts, CI workflow, preserved run-8 artifact, and independent measurement review. I ran no build, test, lint, typecheck, formatter, or server command and changed no implementation/config/status files.

## Canonical runner obligations

The public boundary is already [`SimulationInput`, `SimulationRunner`, and `ShotSimulation` in `types.ts`](../../packages/game-protocol/src/types.ts), with runtime schemas in [`schemas.ts`](../../packages/game-protocol/src/schemas.ts). The request is `{state, command, config}`; output is `{shotId, settledBodies, facts, frames, durationMs, termination:'settled'}`. `SimulationInputSchema` does not currently exist. Before world creation, the implementation must compose existing `parseMatchState`, `parseGameCommand`, and `CounterballConfigSchema` validation, verify version/config compatibility, exact 15 unique IDs and finite/normalized body transforms, legal phase/status, configured parameter bounds, and selected-cap ownership. Turn/room/authenticated actor authority remains application/server work; the runner derives the normal selected side from `state.activeTeam` and the restart selected side from `state.restart.awardedTeam`. A normal `shot` must not run in `restartPlacement`; `restartShot` must not run in ordinary `ready`.

For a normal shot, restore the supplied snapshot into a fresh world and apply only the configured planar impulse derived from `yaw` and `power` at the configured strike point. Do not accept client-computed forces. For `restartShot`, validate restart presence/reason/anchor, require the chosen owned cap and its configured anchor tolerance/surface height, relocate only that selected cap, preserve every other cap transform, and derive the button pose from `capPosition`, `buttonAzimuth`, `buttonTilt`, and shared geometry. The only current button-pose calculation lives inside the calibration test; putting a second formula in the runner and then another in T07 would create drift. Have the coordinator define one pure, tested pose helper for both the runner and future placement/referee consumers, or explicitly name an existing canonical helper before dispatch. Root owns any shared package/export edits.

The runtime loop must use one public stepping route (`HavokPlugin.executeStep`) at exactly the configured 1/120-second interval; do not let Babylon’s render loop step the same authority world. Collect collision callbacks at every physics tick and map body handles to stable `EntityId`s. Normalize/deduplicate contact facts by fixed step and stable ID ordering. The canonical point is required and finite; if a callback does not supply a finite point, define a deterministic geometry-based fallback or fail safely instead of emitting invalid JSON. Derive crossing facts from swept transforms for the button and caps, with whole-button goal/out geometry and crossing-fraction time; do not inspect downsampled frames for rule facts. Preserve facts at every decisive step, order by step/time and stable tie-break IDs, put contact before crossing on a same-step tie, and throw `resourceLimit` if the 8,192-fact bound is exceeded.

Produce the initial frame at time zero, a frame every four ticks (30 Hz), and one exact final frame even when settling ends between sample ticks. Each frame has all 15 pose-only transforms in stable ID order; the final frame must agree with `settledBodies`, and frames/facts/duration must parse as finite canonical output. Enforce the 451-frame and 8,192-fact bounds; never truncate decisive facts or report a capped shot as settled. Continue until all 15 movable bodies remain under both settle thresholds for the configured continuous window; at the 15-second limit throw typed `timeout`. Detect nonfinite simulation transforms/velocities as `invalidBody`; classify WASM/world setup errors as `initialization`; classify allocation/fact/frame/workload limits as `resourceLimit`. Add a bounded workload guard separate from the simulated-duration cap and yield between batches so worker/browser cancellation can run.

Cancellation is a shared-interface gap: [`SimulationRunner.simulate(input)`](../../packages/game-protocol/src/types.ts) has no signal or cancellation result today, and `SimulationErrorCode` contains only `initialization|timeout|invalidBody|resourceLimit`. Do not insert `AbortSignal` into serializable `SimulationInput` or silently map cancellation to another failure. Coordinator must define an optional non-wire signal/options argument and cancellation error/result semantics, consistent with GAMEPLAY’s requirement to preserve the pre-shot checkpoint and emit an aborted action upstream. Each simulation uses a private input snapshot and isolated world; always remove observers, dispose the world and release native resources in `finally`, including on cancellation. Return no partial settled result on any failure.
