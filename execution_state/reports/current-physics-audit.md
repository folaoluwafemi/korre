**Review scope:** read-only source and evidence audit on 2026-10-10. No local build, test, typecheck, lint, formatter, physics run, or server was started. No source or shared configuration was changed during this audit.

## Findings that should be repaired before treating the loft probe as useful evidence

### 1. The intended-shot probe still ignores D38 and its clearance predicate measures a peak

`games/counterball/src/simulation/intendedShotProbe.test.ts:95-97` hardcodes `clearanceEpsilon` to `null` and says the canonical config has no such field. That is now stale: D38 added `COUNTERBALL_CONFIG_V1.restart.clearanceEpsilon = 0.005` in `packages/game-protocol/src/config.ts:42-47`, with type/schema/test/hash updates. The probe also asserts that the value and classification are null at lines 741-742 and emits `clearanceClassificationAvailable: false` at lines 795-798. A new hosted artifact would therefore omit the agreed diagnostic threshold even though it is in the canonical config.

Simply replacing the null with the config value would expose a second defect: lines 520-526 collect the **maximum** signed clearance while center distance is within the sum of the nominal radii, and lines 558-562 compare that maximum to epsilon. This is a peak-height test in a conservative radial window. It does not prove that the button passed from the near side to the far side of the obstacle while remaining clear throughout the overlap. A momentary peak can pass this predicate before the button descends into the cap, or while the button never makes a complete crossing. It would contradict D38 and `CONTRACTS.md:124` to label it a traversal pass.

The preserved run-18 artifact makes the false-positive risk concrete. Its maximum is `0.33800213296016723` at tilt 60° / impulse 8, but its minimum sampled clearance within that window is `0.000948813`, below D38's `0.005` margin. Seven of the eight rows with positive maxima would meet a naive `maximum >= 0.005` check; none has complete near-side-to-far-side evidence in the artifact. The rows do not preserve horizontal position for each clearance sample, so this artifact cannot be reclassified into a traversal result after the fact. See `execution_state/reports/T02-B2-artifact-review-run-18.md` for the independently verified artifact data.

Keep peak clearance as a clearly named diagnostic. For a future classification, capture the approach path and prove an actual complete transit; evaluate the **minimum** signed vertical clearance over the entire horizontal shape-overlap interval, including the entry and exit boundaries. Account for orientation-dependent projected support and interpolate/sweep between physics ticks so a fast path cannot skip the overlap. A tri-state result is appropriate: `true` only for a complete transit whose minimum clearance is at least the configured epsilon; `false` for a completed trial that demonstrably did not meet the condition; `null` when there was no measurable overlap, no complete transit, or the path evidence is insufficient. Preserve the raw peak and raw per-step measurements separately. The current artifact lacks the needed path information, so rerun the hosted real-WASM probe after the repair.

### 2. A settled window reached on the final allowed physics step is reported as a timeout

In `games/counterball/src/simulation/intendedShotProbe.test.ts:536-539`, a quiet window is accepted only when `step < maximumSteps`. If the final step completes the configured quiet window exactly at the 15-second cap, the probe leaves `allBodiesSettledAtSeconds` null and reports the full duration as if the trial did not settle. This is an off-by-one acceptance bug at the boundary. Accept the completed quiet window at `maximumSteps` as settled; the 15-second bound still holds. Add a focused boundary regression to the existing probe assertions.
