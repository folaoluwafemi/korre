## Technical and acceptance review

The native producer has a concrete browser-only API and output contract: `runNativeContactOnsetProbe({engine, signal})` returns a serializable `NativeContactOnsetProof`, with no native handles. The accepted public `LoftContactSubscription` record is exposed in the result. The exact five phase names and call counts are specified: `separated-before` (1), `first-contact` (1), `sustained-contact` (60), `separated-after` (1), and `recontact` (1), at the configured 1/120-second step, for 64 calls total. It records actual before/after body states and every raw per-body notification, including mirrored rows; it forbids callback filtering, deduplication, and truncation.

The initial-overlap negative check uses the accepted `nativeAabbOriginRadius` and `isLoftStartSeparated` helpers with measured native bounds/poses before any step. It records `startsBefore:false` and `actualCallsBeforeCheck:0`, then restores the controlled setup. This is the right contract seam: the probe must call the accepted helper rather than copy the production calculation or use configured geometry as a substitute. The controlled lifecycle then checks real Started notifications on both observers, no Continued rows during sustained support, no pair rows while separated, and a fresh mirrored Started episode after recontact. It requires the negative fall and supported hold evidence, rather than treating an empty event stream as proof of contact.

The setup is sufficiently concrete for an implementer: reuse the caller-owned page `Engine`, pinned browser Havok/WASM, current world factory, canonical 15 dynamic plus 7 static body order, and accepted onset adapter. It parks unrelated dynamics away, uses public TELEPORT/velocity/`executeStep` operations, keeps world gravity, motion types, filters, and solver behavior unchanged, and disposes the temporary world/removes all 22 observers without disposing the caller's engine. The apron top is derived from its actual native AABB and pose; the packet explicitly allows the pinned runtime's measured Float32 top to be at or above configured `surfaceY` and forbids substituting a literal zero or requiring configured-zero equality.

The UI contract is bounded to a clearly labelled development diagnostic with the specified run/status/result/error selectors. The existing diagnostic browser spec is the integration surface. `OPERATIONS.md` confirms the routed diagnostic configuration selects that existing spec and that C01-H requires exact collection; it also requires the hosted CI sequence and full logs/artifact provenance. No new local app command, mock, workflow edit, or route is needed.
