# T02-L01 CONTACT-ONSET native proof interface readiness

## Readiness

The pinned browser path has the public APIs needed for a small real-Havok onset probe. Reuse the current `Engine` from `CounterballDirectProbe.tsx`, initialize the pinned browser Havok runtime, and create a temporary 22-body world through `createCounterballWorld`. After the onset adapter is independently accepted, pass its exact 22-body readback record into this controlled probe. Keep this result labelled **controlled native collision diagnostic**; it is not the loft calibration, a matrix case, or physics/playability acceptance.

The future module boundary can stay narrow: `games/counterball/src/simulation/nativeContactOnsetProbe.ts` owns the browser-Havok procedure and result facts; `games/counterball/src/browser.ts` exports it for the existing browser harness; `apps/web/src/CounterballDirectProbe.tsx` adds a clearly labelled control/result; the coordinator owns the existing Playwright E2E spec. Do not change the physics runner, config or contact policy as part of this probe interface.

## Deterministic phase sequence

Use an isolated `button` / `support-apron` pair for the contact lifecycle. It gives a stationary static partner that gravity keeps in contact without changing Havok filters, solver settings, world gravity or body motion types. Derive every coordinate from `COUNTERBALL_CONFIG_V1`; do not hard-code a second geometry default.

1. Create the ordinary world from the accepted fixture with the caller-owned browser `Engine`. `worldFactory.ts:185-187` sets the configured 1/120-second time step; it creates 15 dynamic cylinders and seven static bodies (`:224-265`, `:296-308`). Before the first step, set `PhysicsPrestepType.TELEPORT` on every dynamic body, set identity rotation and zero linear/angular velocity, and park the button at `(0, surfaceY + buttonThickness/2 + 10, 0)`. Park each of the other 14 dynamics at a distinct x coordinate starting at 4 with spacing 2, at that same height. The slab and goal colliders remain unchanged at their factory poses. Record the slab top as apron pose Y + its native local AABB maximum Y and require exact equality with configured `surfaceY`. This yields a real, separated negative interval with no unrelated pair near the button.
2. Build the adapter input explicitly in contract order: each of the 15 IDs from `ENTITY_IDS` looked up by ID, then goal-frame IDs 0 through 5 and `support-apron` looked up by static node name. Do not use `Map.values()` or `world.staticBodies` order: the factory stores the apron first, then the six frames, while the contract requires the apron last. Call the accepted helper with the initialized runtime's actual `EventType.COLLISION_STARTED` wrapper. Require its exact mask/readback facts for all 22 before any step. Add one observer to each body's `getCollisionObservable()` and retain every delivered row with the observing body ID, other ID, and event type.
3. Execute one fixed call at `1/120` with the existing `world.plugin.executeStep(delta, physicsEngine.getBodies())` path. The initial button/apron separation is 10 game units; require zero pair rows and verify separation from the recorded native local bounds: button bottom = button pose Y + native local minimum Y (identity rotation), apron top = apron pose Y + native local maximum Y.
4. Teleport the button to `(0, surfaceY + buttonThickness/2 - 0.002, 0)`, zero its velocities, and execute one `1/120` step. Require a native `COLLISION_STARTED` row for `button`/`support-apron` from each per-body observer, retaining both mirrored rows. No callback filtering or deduplication is allowed.
5. Leave the button untouched and execute a second `1/120` step. Require button pose Y + native local AABB minimum Y (identity rotation) to remain within 0.001 of the previously measured native apron top (which must equal `surfaceY`), its y-position to change by less than 0.0001 across this step, and its vertical speed to remain below the configured settle threshold. Require that the observer stream has added no row and contains no `COLLISION_CONTINUED`. This binds the no-continued assertion to a supported contact interval rather than an idle separated pair. If Havok does not hold this controlled pose, report the probe as failed; do not infer sustained contact from an empty event list.
6. Teleport the button back to the high separated position, zero velocities, and step once. Verify native bounds now show separation and that no new button/apron start was recorded. The onset-only contract does not subscribe to a Finished event, so do not expect or require one.
7. Teleport the button back to the same 0.002-unit support overlap and step once. Require a second onset episode, again preserving each delivered mirrored `COLLISION_STARTED` row. This tests separation followed by re-contact under the same all-22 mask setup.
8. Independently exercise the initial-obstacle rejection guard before stepping: place the button and `home-1` at same y with a center-z gap below the sum of their actual native z extents, then evaluate the exact `startsBefore` inequality using the native `farthestOriginRadius` values. Assert false, restore the controlled button/apron setup, and only then start the event sequence. This check establishes that an initial obstacle overlap is ineligible even if an onset row is absent; it must not be presented as a callback result.

Record the phase boundaries, body IDs/poses, all 22 requested and observed masks, every raw observer notification and the check results. Fail the probe on an unexpected event type, missing mirrored observer, extra unrelated contact, lost support, or failed readback. Remove all 22 observers and dispose the temporary world in `finally`; do not dispose the caller's `Engine`.

## API evidence and concrete risks

- `PhysicsBody.setPrestepType/getPrestepType` are public (`games/counterball/node_modules/@babylonjs/core/Physics/v2/physicsBody.d.ts:162-167`). The enum exposes `TELEPORT` (`Physics/v2/IPhysicsEnginePlugin.d.ts:340-346`). In pinned `havokPlugin.js:1333-1384`, TELEPORT synchronizes the transform node through `HP_Body_SetQTransform` before stepping. `executeStep` performs pre-step transforms, native world stepping, sync, then collision notifications (`Plugins/havokPlugin.js:578-607`). This is the correct public transform/step sequence; do not mutate native body IDs or call a private plugin method.
- `PhysicsBody.setLinearVelocity`, `setAngularVelocity`, `setMotionType`, and `setGravityFactor` are public (`physicsBody.d.ts:151-167, 251-297, 409-417`). The proposed sequence leaves canonical dynamic/static motion types and world gravity unchanged; moving bodies high and using only five fixed calls avoids unrelated floor contacts. The per-body gravity-factor API need not be used.
- `PhysicsBody.getCollisionObservable()` returns the per-body observer without changing its mask (`physicsBody.js:449-450`; plugin `havokPlugin.js:2425-2434`). Adding observers on both colliders is how the mirrored callbacks are measured. Do not call `setCollisionCallbackEnabled(true)` after the adapter: pinned `havokPlugin.js:2456-2467` resets the mask to Started|Continued|Finished. The all-22 set/readback record must describe the masks that remain active when the first step starts.
- A concrete ordering hazard is present: dynamic-body map order is fixture insertion order, while static factory order starts with `support-apron`. The probe must build both lists by explicit canonical IDs/names, or the accepted adapter should reject the input before any physics.
- The current `startsBefore` test is inline in `loftCoarseRunner.ts:2373-2380` and uses native `farthestOriginRadius` metrics. The proposed files alone cannot invoke that production eligibility calculation or read the runner's per-case metric object. The controlled probe can independently verify the same rejection only if it derives those exact native radii through an already accepted shared helper; it must not substitute configured radii or claim it exercised the runner's eligibility result. If the acceptance criterion requires production-predicate execution, first give that predicate/metric calculation a minimal shared/testable source seam in a separately scoped change; do not duplicate its radius math and label the copy as production behavior.

No code or runtime check was performed for this readiness report. It does not prove native onset delivery, exact masks in a browser, event counts, or matrix fit.
