## Contract and implementation scope

The exact five write paths are sufficient and disjoint at dispatch time: `loftCoarseRunner.ts`, `loftCoarseProbe.ts`, `loftCoarseProbe.test.ts`, `tests/e2e/counterball-direct-probe.spec.ts`, and the new internal `nativeCylinderSupportDatum.ts`. The accepted contract in `knowledge_base/execution/completion/CONTRACT_WORK.md` and proposal review 2 defines a conservative datum from the actual native cylinder AABB and COM: `referenceY + min(radius, halfHeight) - norm(localCOM)`. Its prerequisites are strict centered/symmetric finite bounds, equal positive X/Z spans, a supported native cylinder type, and a measured support plane. The formula is coherent with the cylinder's minimum vertical support and arbitrary local-COM offset; unsupported geometry must remain a typed resource failure.

The current runner already reads native shape bounds and dimensions for each dynamic body and static body (`loftCoarseRunner.ts` around lines 426, 959, and 1114). The accepted pure `nativeCylinderComRadius` helper uses canonical `Vec3` inputs and does not create a competing public API. The new datum helper can use that same canonical vector/bounds representation. The runner currently sets the energy/drop reference once at `metric.restY = sample.centerOfMass.y` (around line 1555); replacing this with the verified datum makes the already shared support, energy, and sweep checks use one reference. The contract keeps the raw measured values for calculations and serialized facts.

The packet correctly requires actual support-plane evidence: observed native box type/AABB and transform, parent and scale state, `referenceY`, and `nativeTopY = position.y + nativeLocalAabb.maximum.y`. The runner, writer, and host must all enforce identity rotation, unit scale, no parent, finite exact bounds, and `nativeTopY >= referenceY`; the writer and host recompute the datum from the emitted native bounds and COM. This prevents a producer from substituting configured dimensions or a configured plane for native evidence. If Babylon's transform uses identity Euler rotation with a null quaternion, the emitted identity quaternion must be derived from the observed zero Euler rotation, as noted in the interface audit.

The strict writer metadata/key validators are centralized in `loftCoarseProbe.ts` (case keys around line 323; dynamic-body keys around line 342; dynamic validation around line 750). The probe fixture factory and focused unit cases live in the assigned test file. The host's parallel validation is already centralized in `counterball-direct-probe.spec.ts` (`validateCaseMetadata` around line 880 and `validateMatrixCase` around line 1451). Those paths can add the new strict raw fields, test fixture metadata, and independently recheck datum/support-plane relationships without changing protocol payloads or adding a new test file.
