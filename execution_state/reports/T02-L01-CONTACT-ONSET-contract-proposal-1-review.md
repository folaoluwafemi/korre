# T02-L01 collision-onset proposal 1 review

**PROPOSAL: PASS for freezing/accepting prose policy and interface scope only. CONFIG/ADAPTER SOURCE, RUNTIME, AND BUDGET: NOT ACCEPTED/VERIFIED. MATRIX: NOT ACCEPTED.**

The proposed native `COLLISION_STARTED`-only subscription preserves the matrix's existential “did button and obstacle ever touch?” check, provided the specified checks and native tests are implemented before matrix acceptance. It intentionally changes the contact log from all event kinds to all delivered onset callbacks. The strict hashed policy and new config/guard/algorithm versions make that evidence change explicit; this is not silent post-callback filtering.

The current runner derives the initial whole-body separation from the actual native local-AABB bounding radii: `startsBefore` requires the button's initial z extent to end strictly before the obstacle's initial z extent (`loftCoarseRunner.ts:2373-2380`). That predicate uses the saved initial samples, so a case with an initial overlap cannot become eligible even if the engine does not emit a new onset for a pre-existing pair. The callback observers and masks are installed before the first impulse/step (`:1782-1835`), so any later transition from separated to touching is in the subscribed interval. A contact onset is sufficient evidence for an any-contact exclusion; continued rows describe persistence, and finished rows describe termination. Keeping every delivered start, including mirrored notifications and later re-contact episodes, retains the evidence that matters to this predicate.

There is also an independent geometric guard. Before every public physics call the runner checks the button/obstacle's conservative whole-cylinder vertical clearance, including the combined point-sweep bound (`loftCoarseRunner.ts:797-834`, `:2064-2109`). A case only passes clearance when every interval with horizontal overlap remains strictly above the existing `0.005` margin; any observed button/obstacle contact independently makes it ineligible (`:2279-2288`, `:2383-2413`). The proposal leaves these checks, geometry, 24 tuples, settlement requirements, per-call limits, and the `8,192` per-case / `196,608` matrix contact caps intact. If genuine onset episodes alone exceed a cap, the matrix must still fail without a success artifact.

The pinned workspace sources support the public API route. Babylon 9.30.0 exposes `PhysicsBody.setEventMask` and `getEventMask` (`node_modules/.pnpm/@babylonjs+core@9.30.0/node_modules/@babylonjs/core/Physics/v2/physicsBody.d.ts:134-145`); its implementation forwards these to the plugin, which calls the pinned Havok `HP_Body_SetEventMask` and reads `HP_Body_GetEventMask` (`Physics/v2/physicsBody.js:181-195`; `Plugins/havokPlugin.js:982-1007`). Havok 1.3.14 declares its event mask as an OR of the selected `EventType` values (`node_modules/.pnpm/@babylonjs+havok@1.3.14/node_modules/@babylonjs/havok/HavokPhysics.d.ts:330-333`). Babylon's `setCollisionCallbackEnabled(true)` writes Started, Continued, and Finished together (`havokPlugin.js:2456-2467`), so the implementation must use the public per-body mask API and must not leave a later enable call that restores the broad mask. Its event drain dispatches each native collision to the global observable and then to the participating per-body observables; the second body receives a reversed pair (`havokPlugin.js:2518-2581`). The proposed 22-body exact readback and retention of all symmetric callbacks therefore match the pinned adapter surface and do not require private native body-ID access. The Started enum value must be derived from the initialized pinned runtime through a checked `unknown` boundary and rejected before physics if its shape/value is unexpected; do not infer its numeric value from the declaration's implicit ordinals.

The previous full-browser attempt does not show that the new stream will fit. Run `38643635405`, commit `6c88ecc0cbc43c57b887a5f929cc9e0a46cad8ab`, failed in the first tuple at nominal tick 4 / 240 `executeStep` calls with zero completed cases and no matrix download. Its retained error reports only the aggregate contact-row ceiling failure; it contains no pair/event breakdown. The proposal's persistent-floor explanation is therefore a source-based hypothesis, not an observed distribution or proven cause. The onset-only policy may reduce ongoing-contact rows, but the unchanged caps and full matrix run must establish whether it fits.

### Acceptance boundary

The proposal review permits the coordinator to freeze and accept the prose policy/interface scope. That step defines the versioned diagnostic semantics only; it does not accept the config producer, adapter implementation, native event behavior, contact-row budget, or L01 matrix. Check 1 below is required for the config/schema producer acceptance; check 2 is required for the adapter/source acceptance; check 3 is required before claiming the onset policy has runtime proof; and check 4 is required for L01 matrix acceptance. These are sequential evidence gates, not prerequisites to writing down the contract.

The following checks are required at their matching stages:

1. Strict config/schema tests for the four exact hashed `contactPolicy` literals; updated config/guard/algorithm identities; rejection of old identities and malformed/missing policy fields; recomputation of all eight fixture `configHash` leaves and the raw fixture byte pin; unchanged omitted-hash payload digest, physical values, tuple list, and contact caps.
2. Focused source/writer/host tests that derive a positive single-bit Started mask from the initialized runtime, set it on all 22 bodies in canonical order, and require exact readback before impulse or step. A missing body, invalid enum shape/value, setter/readback mismatch, unexpected delivered event type, malformed policy record, or wrong/missing host mask must fail closed. Verify all delivered Started rows remain in occurrence order, including both mirrored notifications; there is no filter, dedupe, or truncation, and all existing row/byte limits remain strict.
3. Real Chromium with the pinned Havok WASM must prove a separated pair's first actual contact yields the expected per-body Started rows; sustained contact adds no Continued rows; separation and re-contact yield a new Started episode; and a separated negative case yields no pair rows. Also prove the initial whole-button-before-obstacle predicate rejects an initial-overlap case independently of absent onset callbacks. Mocks alone do not establish native event delivery.
4. Then run and independently inspect the complete real-browser 24-tuple matrix, exact host validation/download/acknowledgement and artifact. It must meet every frozen zero-skip/retry/flaky condition and every unchanged bound. A smaller native onset test passing is not L01 matrix acceptance.
