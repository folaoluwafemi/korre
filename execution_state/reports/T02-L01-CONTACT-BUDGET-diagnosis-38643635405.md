## Addendum — supported public mask API correction

The pinned workspace copy at `games/counterball/node_modules/@babylonjs/core/Physics/v2/physicsBody.d.ts:134-145` exposes public `PhysicsBody.setEventMask(eventMask, instanceIndex?)` and `getEventMask(instanceIndex?)`. Its implementation at `physicsBody.js:181-195` forwards to the plugin; the pinned Havok plugin at `Plugins/havokPlugin.js:982-1007` applies the mask to the native body and reads it back. Thus a private `HP_BodyId` lookup is **not required** for these non-instanced bodies. The coordinator's proposed path can use the public body methods, explicitly set the per-body mask, and require exact `getEventMask()` equality for each of the 22 bodies before the first physics step. The earlier paragraph saying a supported body-ID access path still had to be established is superseded by this finding. `setCollisionCallbackEnabled(true)` remains unsuitable for this policy because it overwrites the mask with all three collision event kinds.

One type-boundary detail remains: the pinned `HavokPhysics.d.ts` declares `EventType` as a TypeScript enum, while the runtime plugin code reads enum wrappers through `.value` (for example `havokPlugin.js:2458`). The adapter must derive the started bit from the actual pinned runtime representation without an unchecked `any` cast: treat the runtime value as `unknown`, validate the expected object/`value` shape and a finite integer bit value, and fail closed before physics if the shape/value is unexpected. Then set that derived mask through the public `PhysicsBody` API and require exact numeric readback. Do not infer the runtime bit from the declaration's implicit enum ordinals or hard-code an unverified bit. The existing limits, callback ordering/duplication, sweeps, and runtime acceptance boundary remain as stated above.
