## Findings to resolve before source implementation

1. **Define the shifted-energy equation and pre-impulse check.** Proposal lines 23–25 name “total shifted mechanical energy” and a candidate-relative rest reference but do not freeze its exact computation or explicitly require checking the predicted post-impulse value before applying the impulse. Add the equation to the contract and packet, using each body’s actual native mass, world-space inertia, COM velocity, and candidate-specific starting COM height. For example:

   `Eshift = Σi [ ½ mi |vi|² + ½ ωiᵀ Iworld,i ωi + mi g (COMy,i − (restY_i − 0.01125)) ]`.

   With all bodies at rest and the impulse applied at the selected cap’s native COM, preflight the actual native values using `J²/(2 m_home-0) + g × 0.01125 × Σmi <= 34` before applying it. Do not silently substitute configured `1` and `14.15` if native mass readback differs. Reject non-finite or out-of-domain data before the impulse. The current “within reviewed conservative bounds” phrase does not state the numeric bounds or that actual-mass inequality.

2. **Retain substep guard extrema in the artifact.** Proposal line 31 records nominal-tick body transforms and swept summaries, but those summaries omit the maximum shifted energy and maximum candidate-relative COM drop actually checked across the tick’s substeps, and the minimum conservative apron/slab-underside support margins. Nominal endpoint transforms cannot reproduce those values. Add these extrema (and the existing checked-call count) to each tick’s compact summary, with finite checks and the existing row/byte caps. This lets the independent raw-artifact review verify the guard evidence without storing every substep transform; it still must be labelled finite-step, bounded evidence.

3. **Update the L01 packet and contract before dispatch.** The current exact packet says its guard is “C00-frozen,” that values stay within C00-B/the existing tested envelope, and to stop if that guard is not frozen. The accepted C00/GC02 guard is `browser-direct-impulse-v1` for D01 only; it does not authorize restart inputs. Before a source worker runs, coordinator-owned contract/schema work must explicitly accept this separate L01 scope, include its identity and limits in the strict canonical config hash, update the config schema/hash fixtures, and revise the L01 packet’s guard/dependency wording to name the new guard. The hash claim at proposal line 11 also needs literal protocol/physics/fixture/WASM identity fields inside the hashed config object: `hashCounterballConfig()` hashes `CounterballConfig` only, while protocol and physics version stamps are assembled separately. The fixture SHA listed in the proposal matches the current `tests/fixtures/counterball-v1.json` bytes; the schema still needs to make the other claimed identity values actual hashed fields and compare loaded WASM bytes before the impulse.

## Workload and remaining proof

The proposed 720,000-ms aggregate wall limit differs from the earlier workload report’s provisional 540,000-ms/9-minute allocation. This is a coordinator policy choice, not an arithmetic contradiction: the proposal explicitly disclaims a fit guarantee, and the historical 2:24 full-pipeline time is not an L01 benchmark. Keep that limitation visible and require a successful exact-head hosted run within the existing job timeout before accepting any result. If it exceeds the cap or job deadline, fail without a success artifact; do not shorten the matrix.

The total-energy and sweep arguments remain conditional on measured native masses/inertias, material readback, bounded gravity/force behavior, and actual per-call conservative checks. The diagnostic apron assumes every synthetic initial collider fits within the painted pitch; the prescribed selected/obstacle/filler positions do. This proposal and its arithmetic do not prove those checks are implemented or safe in the pinned browser runtime. The next contract/schema card must also keep the exact tuple/setup order and limits in the hashed field, make all output failures non-success, and preserve `physicsCalibration: null`.
