# T02-GR01 pinned API audit review

**Verdict: PASS.** I found no correction required in the API semantics or geometric-envelope argument. The report correctly keeps the envelope conditional on validated geometry and genuinely valid speed bounds, and does not claim that the pinned APIs certify a full Havok swept path.

## Checked package versions and paths

The workspace manifest `games/counterball/package.json` pins `@babylonjs/core` 9.30.0 and `@babylonjs/havok` 1.3.14. The installed package metadata at `node_modules/.pnpm/@babylonjs+core@9.30.0/node_modules/@babylonjs/core/package.json` and `node_modules/.pnpm/@babylonjs+havok@1.3.14/node_modules/@babylonjs/havok/package.json` confirms those versions. I checked the declarations and implementation under those exact roots, including `Physics/v2/physicsShape.d.ts`, `Physics/v2/physicsBody.d.ts`, `Physics/v2/IPhysicsEnginePlugin.d.ts`, `Physics/physicsShapeCastQuery.d.ts`, `Physics/v2/Plugins/havokPlugin.d.ts`, `Physics/v2/Plugins/havokPlugin.js`, and Havok's `HavokPhysics.d.ts`.

## Findings

- **Shape geometry and bounds:** Babylon's cylinder constructor accepts `pointA`, `pointB`, and `radius` (`physicsShape.d.ts:205-220`); the Havok plugin forwards those points and radius to `HP_Shape_CreateCylinder` (`havokPlugin.js:1535-1538`; `HavokPhysics.d.ts:252`). The public shape API has no exact radius/endpoint readback. Havok's bounding-box API accepts one transform (`HavokPhysics.d.ts:295`), and Babylon's shape getter calls it at identity (`havokPlugin.js:1764-1773`); the body getter transforms that box at the current pose. The factory constructs the dynamic cylinders from symmetric configured endpoints (`games/counterball/src/simulation/worldFactory.ts:303-307`). Thus obtaining exact geometry from the canonical constructor inputs, and treating AABBs as current-pose bounds rather than shape introspection or sweeps, is sound.
- **Mass-property semantics:** Havok declares the tuple as center of mass, mass, inertia for mass 1, and inertia orientation (`HavokPhysics.d.ts:110-115`); Babylon's mass-property declaration agrees that inertia is for unit mass (`IPhysicsEnginePlugin.d.ts:286-327`). The plugin's `getMassProperties` reads `HP_Body_GetMassProperties`, the configured native state (`havokPlugin.js:1133-1137`; `HavokPhysics.d.ts:336-337`). In contrast, `computeMassProperties` rebuilds from the shape and falls back to `[0, 1, (1,1,1), identity]` after a failed native query (`havokPlugin.js:1087-1108`). The audit correctly distinguishes these paths and warns against using the recomputation fallback as evidence of active-body values. It also correctly notes that the wrapper discards the native result code when reading the tuple.
- **Shape casts and stepping:** Babylon's shape-cast query provides a single rotation and start/end positions (`physicsShapeCastQuery.d.ts:7-23`); the raw Havok `ShapeCastInput` likewise has one orientation and translational endpoints (`HavokPhysics.d.ts:180-193`). The plugin forwards that fixed rotation and those endpoints to Havok (`havokPlugin.js:2390-2415`). This is not a continuously rotating cylinder cast. `setSubTimeStep` is only a timestep setting (`physicsEngine.d.ts:56-66`), while the plugin step sets ideal step time and calls `HP_World_Step` (`havokPlugin.js:603-605`); neither declaration promises intermediate transforms or a sweep certificate. The audit's limitation is accurate.
- **Geometric envelope:** For a cylinder with radius `r` and endpoint separation `h`, every point lies within `sqrt(r² + (h/2)²)` of its geometric center. If the validated local COM offset magnitude from that center is `c`, the triangle inequality gives a conservative COM-centered radius `c + sqrt(r² + (h/2)²)`. If COM displacement from its pre-step location is bounded by `vBound * dt` over the entire interval, a sphere centered at the pre-step COM with radius `rMax + vBound * dt` contains the collider at every instant, regardless of orientation. The angular speed term is appropriate for the separate point-travel bound `(vBound + omegaBound*rMax)*dt`; it is not needed to enlarge that enclosing sphere. The report states these as conditional mathematical bounds and preserves the need to validate their premises and check the entire candidate interval.

The report's conclusion is appropriately narrow: source geometry, current mass values, and sampled velocity are available, but the package API does not prove the solver's complete within-step trajectory or non-tunnelling. This review inspected source and declarations only; it ran no application, physics, browser, or deployment checks and proves no Havok runtime behavior.
