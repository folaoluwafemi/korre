## Required outputs

1. Exact TypeScript types for the canonical match state, body, commands, control envelope, simulation facts/results, wire events, room command/view, and protocol error codes.
2. Strict Zod v4 runtime schemas at wire boundaries. Reject unknown command keys, non-finite/out-of-range values, unnormalized quaternions beyond documented tolerance, missing/duplicate entities, incorrect 15-body counts, invalid powers/angles, and malformed event/room payloads. Return typed, actionable parse errors without silently coercing values.
3. One deeply immutable v1 base config from numeric settings stated in `DECISIONS.md`; a stable canonical JSON serializer and SHA-256 hash helper. Do not add guessed physics calibration coefficients in this task. Any adapter parameters must remain an explicit T02-owned input/extension until T02 selects them.
4. Helpers `oppositeTeam` and cap-to-team ownership mapping with unit tests. Angle conversions are single-boundary helpers only if needed; wire angles remain radians.
5. SDK `GameManifest`, `GameModule.mount`/`dispose`, and one `GameTransport` contract supporting typed send, connect, snapshot, subscription, and disposal. Platform state stays separate from Counterball match state. The manifest is Counterball, two players, spectators enabled, modes `ai` and `online`.
6. A fixture set with one initial 15-body state and foul/out/goal/penalty/blocked scenarios. Every scenario carries protocol/game/rules/physics/config version tags. These are deterministic protocol/rule fixtures, not physics measurements or deployed Havok proof.

## Acceptance

1. All fixture JSON parses through the exported schemas; initial state has exactly 15 unique legal bodies and valid transforms.
2. Tests cover duplicate/missing IDs, extra command fields, invalid/non-finite power and vectors, quaternion normalization, config hash length/algorithm, canonical-hash stability under object key insertion order, and distinct canonical output/hash for an own `__proto__` key.
3. The domain helpers return `oppositeTeam(home) === away`, vice versa, and map all seven cap IDs to exactly one team.
4. An example local transport and network transport typecheck against the same `GameTransport`; neither SDK nor protocol imports Babylon, React, Hono, pg, or Cloudflare.
5. Manifest/mount types represent two players, spectators, AI/online modes, and idempotent disposal without placing platform membership/identity inside `MatchState`.
6. T00 checks remain green; T01 is accepted only after independent review and coordinator integration checks.
7. Protocol-v1 bounds reject oversized arrays, simulation facts, playback frame counts/chunks, invalid chunk indexes, oversized encoded chunks/snapshots, and overlong room waiting lists.
