# Runtime decisions

- Workspace shape follows the user's explicit monorepo choice and `knowledge_base/execution/DECISIONS.md`.
- CI and the documented runtime use Node.js 24.21.0. Local execution may use installed Node 25.2.0 for checks; no runtime switch or install is performed.
- All package versions are exact and listed in `VERSIONS.md`; workers do not install dependencies or modify the lockfile.
- Web/API/realtime local ports are 5173/3001/8787. Port collisions fail rather than silently selecting a different port.
- T00 is only the scaffold. No gameplay, identity, or online match feature is claimed; the local Worker health endpoint is not the deployed Havok gate.
- T01 protocol config carries `physicsCalibration: null` until T02 selects and records the pinned Havok adapter coefficients. It is not a calibrated physics configuration or Havok result; T02 must replace the pending calibration input and issue a new config hash/version before simulation use.
- T01 review repair fixes protocol-v1 resource bounds in `knowledge_base/execution/CONTRACTS.md`: 8,192 array items/facts, 451 frames/chunks per shot, 32,768 encoded bytes per playback chunk, 1 MiB playback data in a snapshot, 22 room participants, and 20 waiting IDs. These are transport/runtime safety limits, not cultural or physics-tuning decisions.
- T02 coordinator decision D35: add versioned geometry values `goalFrameRadius: 0.06` and `surfaceThickness: 0.20`; the pitch top remains `surfaceY`. These are provisional collision proportions with a new config hash, not measurements. T02 remains the sole owner of later friction/restitution/damping/impulse/lift calibration proposals.
- T01 is authorized to correct only the `test` script paths in `packages/game-protocol/package.json` and `packages/game-sdk/package.json` after both required package-test commands resolved `../../vitest.config.ts` outside the workspace root. This adds no dependencies and does not require a lockfile change.
- T01 integration repair: the T00 workspace smoke imported `scaffoldPackage` from protocol and SDK; those packages now expose their real contracts, so update the smoke to assert their public APIs. The root test typecheck includes DOM declarations so importing the required SDK `HTMLElement` mount type compiles; tests still execute in Node.
- Docker's local engine is currently unreachable. Database-dependent work remains independent until a real PostgreSQL service is available.
- T11 implementation default D36: registration is limited to five requests per hour per client address; recovery is limited to five per hour per address and case-insensitive username. PostgreSQL stores only keyed HMAC bucket identifiers in `identity_rate_limits`; raw addresses/usernames are not stored. This is an operational security default, not a cultural rule, and requires disposable-Postgres verification before T11 acceptance.
- T02 shared config input D37: initial gravity is `{x:0,y:-9.81,z:0}` game units/s² in the canonical simulation section, included in `configHash` and supplied to every local/Worker world. This conventional acceleration is provisional because world units are arbitrary; loft, impulse, damping, and surface feel still require actual pinned-Havok shot measurements and user playtest.

- Current review decision D38: use canonical restart.clearanceEpsilon=0.005 game units as a provisional diagnostic margin. This technical choice is coordinator-owned, not pending human input. Update fixture hashes with the config change. Preserve raw clearance, distinguish peak height from collision-free traversal, and do not accept T02 or deploy physics until runner/loft/crossing gates actually pass.
- Current review infrastructure: GitHub CI provisions an isolated temporary PostgreSQL 17 service and explicitly opts into loopback-only repository checks. Railway credentials are not needed to verify T11 locally on CI. Build and browser test work stays on GitHub; download only built artifacts for user inspection.
- C00-A protocol decision: `SimulationRunner.simulate` may receive a process-local structural cancellation signal as its optional second argument. The JSON input, command/event envelopes, and persisted match state do not carry a signal. Cancellation uses typed error/event reason `cancelled`, never timeout or successful partial output, and follows pre-shot checkpoint restoration while preserving newer pause/terminal state. This is an additive prelaunch protocol-v1 error reason only if source/deployment inventory confirms no strict active consumer; otherwise version the protocol before release.
- C00-B protocol/config decision: export one `PhysicsCalibration` type with schema version 1, Havok `1.3.14`, adapter `adapter-2`, material/damping/impulse/restart/support/workload/tunnelling fields from `CONTRACT_WORK.md`. `physicsCalibration` remains null in the initial config and historical fixtures. The strict config schema enforces finite provisional bounds plus cross-checks application offset against half cap height and translation per substep against the smallest collider thickness. These values are guardrails, not measured settings; no coefficient or apron is selected here. Canonical explicit substeps call the pinned one-step API repeatedly; unsupported or over-budget motion fails as `resourceLimit`; simulated-time non-settlement alone is `timeout`. The extended invisible pavement support has no wall and cannot alter rule crossing. When a non-null adapter-2 calibration is later selected, C03 must update the physics version stamp and config hash together. C00-B also freezes exact `Resolution`, `validateGameCommand`, stable presentation create/update/pick and `createLocalMatchController` signatures in `knowledge_base/execution/CONTRACTS.md`; those contracts do not claim their code exists.
